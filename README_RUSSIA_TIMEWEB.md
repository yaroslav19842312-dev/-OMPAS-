# КОМПАС Web MVP 1.1 — подготовка к Timeweb Cloud

## Что изменено
- Убран серверный `require()` из движка расчёта; используется обычный импорт.
- Добавлен `/api/health` для проверки работоспособности.
- Добавлены базовые security headers.
- Добавлен `robots.ts` с запретом индексации поисковиками на этапе пилота.
- Добавлен `typecheck`.
- Добавлено ограничение Node.js: `>=20.9.0 <25`.
- Архитектура остаётся без Google-сервисов и без зависимости от Chrome.
- Ответы не сохраняются в базе данных: результат рассчитывается сервером после отправки 56 ответов.

## Рекомендуемый режим Timeweb
Для Next.js с API нужен режим **SSR**. В Timeweb Cloud App Platform при создании приложения выберите Next.js и включите поддержку SSR. В этом режиме платформа предоставляет серверную конфигурацию и запускает приложение командой `npm start`.

Репозиторий с исходниками должен быть приватным, потому что `lib/data.ts` содержит банк вопросов и технические ключи.

## Параметры
- Framework: Next.js
- Node.js: 22 LTS (или другая поддерживаемая версия >=20.9)
- Build command: `npm run build`
- Start command: `npm start`
- Project directory: `/`
- Build directory: оставить предложенную Timeweb настройку для Next.js SSR
- Environment variables: пока не требуются

## Проверка после деплоя
1. Открыть технический домен Timeweb.
2. Открыть `/api/health` — должен вернуться JSON с `ok: true`.
3. Пройти все 56 вопросов.
4. Проверить результат.
5. Проверить мобильный телефон через Яндекс Браузер.
6. Проверить мобильный интернет и Wi-Fi.
7. Только после этого подключать собственный домен и делать постоянный QR-код.

## Важно про российскую доступность
Размещение на инфраструктуре Timeweb в РФ — выбранный вариант для снижения зависимости от зарубежных сервисов. Это не является математической гарантией доступности из любой конкретной школьной сети: перед запуском необходимо провести реальный тест из российской сети, на телефоне и школьном компьютере.
